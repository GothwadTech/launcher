# Internationalisation

**Current state: English only.** There is a single `values/strings.xml` (109 strings), no
translated resource directories, and `resourceConfigurations = ["en", "xxxhdpi"]` in
`app/build.gradle.kts` — so even if a translation existed it would be stripped from the APK until
that list is extended.

`MainActivity.attachBaseContext` already normalises locale handling, and `values-v31/` exists for
API-specific colours, so the plumbing is in place. What is missing is coverage.

## Extraction status

A first pass moved the highest-traffic UI into resources (issues #19/#35): lock screens, the
accessibility alert, search, the Quick Dashboard, settings subtitles and page titles, version
text, the reveal-code dialog, the self-update capability badge, and every dead string was
deleted. Toasts are fully extracted — there are no literal `toast("…")` calls left.

**What remains: 260 hard-coded literals.**

| `android:contentDescription="…"` in layouts | 47 | mostly `sheet_settings.xml` |

Category/page subtitles built by string concatenation in `SettingsMenuHelper` also need format
strings (`getString(R.string.x, arg)`), not `"$a — $b"`.

## Why this was not finished in one go

The strings sit in a 2 000-line layout plus six settings delegates, and this repository has no
compiler available to the person doing the extraction (no JDK/Android SDK in the review
environment). Bulk-editing ~260 references with no compile check is how you ship a launcher that
crashes on `Resources$NotFoundException` at the first frame. So it is deliberately staged:
mechanical, reviewable, verified by CI in chunks.

## How to finish it (mechanical, per file)

For each file, in this order — highest user visibility first:

1. `dialog_pin_entry.xml`, `dialog_pin_setup.xml` (security screens)
2. `dialog_quick_dashboard.xml`, `sheet_notifications.xml`
3. `dialog_search.xml`, `dialog_voice_search.xml`, `dialog_setup_wizard.xml`
4. `sheet_settings.xml` + its Kotlin (largest; split into one PR per settings page if needed)

Per file:

```bash
# 1. list the literals
grep -n 'android:text="[^@]' app/src/main/res/layout/dialog_pin_entry.xml
grep -n 'android:contentDescription="[^@]' app/src/main/res/layout/dialog_pin_entry.xml

# 2. add resources to values/strings.xml (grouped under a comment, snake_case ids)

# 3. replace
sed -i 's|android:text="Enter PIN"|android:text="@string/pin_entry_title"|' <file>
```

Rules:

* **Name by meaning, not by text**: `pin_entry_title`, not `enter_pin`.
* Never duplicate a string that already exists — `grep -n ">Enter PIN<" values/strings.xml` first.
* Use `%1$s` / `%1$d` placeholders and `getString(R.string.x, arg)`; never concatenate in Kotlin.
* Use `<plurals>` for counts.
* Keep `translatable="false"` on brand names, package names and format patterns.
* For content descriptions, write what the control *does*: `@string/cd_toggle_status_bar`.
* After each file, run the reference checker (below) and let CI build.

## Verifying no reference broke

Every `R.string.*` and `@string/*` reference is checked against the resource table:

```bash
python3 tools/check_resources.py   # if present; otherwise:
grep -rho 'R\.string\.[a-zA-Z0-9_]*' app/src/main --include=*.kt | sort -u > /tmp/refs
grep -o 'name="[a-zA-Z0-9_]*"' app/src/main/res/values/strings.xml | sort -u > /tmp/defs
```

CI also runs `lintDebug`, whose `MissingTranslation` / `HardcodedText` checks will flag leftovers
once `abortOnError` is flipped on (see [CI_RELEASE.md](CI_RELEASE.md)).

## Adding a language

1. Create `app/src/main/res/values-<code>/strings.xml` with **all** 109+ keys (partial
   translations fall back to English per key, which is fine).
2. Add the code to `resourceConfigurations` in `app/build.gradle.kts`.
3. Do not translate `values-v31/` colours or any `translatable="false"` entry.
4. TV-specific: some remotes have no keyboard, so avoid strings that assume typing; prefer short
   labels that fit a 960 dp-wide layout at 1.3× UI scale.
